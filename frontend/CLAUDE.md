# CLAUDE.md — frontend/

Inherits the root `CLAUDE.md` and the design system in `DESIGN.md`.

## What it is
A zero-build static PWA (`index.html`, `app.js`, `styles.css`, `config.js`,
`manifest.json`, `sw.js`, `severities.json`). Served by any static host
(`python -m http.server` locally, a Render static site in prod). No framework, no
bundler — one less thing to break at gym wifi speed.

## Data flow (do not break the privacy invariant)
webcam → MediaPipe PoseLandmarker (in-browser) → 33 BlazePose keypoints → a frame
`{t_ms, pose_model:"blazepose_33", people:[{track_id, kp:[[x,y,z,vis]x33], box}]}` →
buffered → `POST`ed to `/prototype/assess`. **Only keypoints leave the browser. Never the
video frame, a canvas, a blob or a data URL.**

## Conventions
- The frame shape is dictated by the backend's `validate_frame_schema`. If the detector's
  expected schema changes, change the frame builder in `app.js` to match — do not guess.
- Send only NEW frames each POST, with `reset:true` on the first call; the server buffers
  per session.
- On a failed POST, put the batch back on the FRONT of the queue. Never drop frames: that
  silently under-counts reps exactly when the network is worst.
- `exercise_id` must be one of `squat`/`pushup`/`lunge` (the API returns 422 otherwise).
- API base URL lives ONLY in `config.js` (`API_BASE_URL`). Deploy = edit that one line, or
  run `set-api-url.ps1`.
- Flag colour comes from `severities.json`, regenerated by `generate_severities.py` from
  `exercises/*.json`. Don't hardcode a severity map in JS.
- Send `z` as the model reports it. The detector computes joint angles in 3D; zeroing z
  breaks front-view rep counting entirely.
- `numPoses` must stay above 1, so a bystander is SEEN and the server's subject lock can
  deliberately ignore them. Setting it to 1 hands the choice to MediaPipe.

## States every screen handles
Loading (model warm-up), camera-prompt, permission-denied (+Retry), running,
API-unreachable (non-destructive banner; buffered frames re-queued, never dropped), empty
summary. See `DESIGN.md`.

An unjudgeable fault renders as a grey "couldn't judge" pill — never as absence. "Couldn't
tell" and "you were fine" are different messages.

## Boundaries
The PWA is a consumer of the detector, never a second implementation of it. Rep counting,
flags and cues come from the API response — do not reimplement any detection or
thresholding in JavaScript.
